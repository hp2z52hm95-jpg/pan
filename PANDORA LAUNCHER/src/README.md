# PandoraLauncher — C sources

These sources build the `PandoraLauncher.exe` that is committed one folder up.

```
cd "PANDORA LAUNCHER/src"
./build.sh                    # -> ../PandoraLauncher.exe   (zig, ~415 KB)
make -C tests                 # host test suite (68 checks)
python3 tools/make-fixtures.py    # regenerate the test fixtures
python3 tools/make-icon.py        # rebuild icon.ico from PandoraTool's resources
```

## Layout

| File | Contents |
|---|---|
| `pandora.h` | all shared types and prototypes |
| `util.c` | string buffer, SHA-256, CRC-32, base64url, INI reader, version compare |
| `json.c` | small JSON parser for the server responses |
| `inflate.c` | RFC 1951 DEFLATE decoder (no zlib), streams through a 32 KB window |
| `zip.c` | ZIP reader/extractor (store + deflate, CRC-32 checked, safe paths, backups) |
| `fs.c` | file system — Unicode (UTF-16) paths on Windows, POSIX for the host tests |
| `url.c` | base-URL parsing + percent encoding |
| `http.c` | WinHTTP client: POST/GET JSON, download-to-file with progress |
| `webauthn.c` | Windows Hello / security-key passkey sign-in via `webauthn.dll` |
| `update.c` | version check, verified download, close app, backup, unpack, relaunch |
| `ui.c` | launcher window + sign-in dialog (plain Win32; the flow runs on a worker thread) |
| `main.c` | startup, `launcher.ini`, the flow, `--self-test` |
| `app.rc`, `app.manifest`, `icon.ico` | icon (PandoraTool's own), version info, privileges |
| `tests/` | `selftest.c` (the suite), `run.c` (host runner), generated fixtures |

Portable modules (`util` `json` `inflate` `zip` `fs` `url`) compile for Linux as
well — that is what makes the host tests possible; `http.c`, `webauthn.c`,
`update.c`, `ui.c` and `main.c` are Windows-only.

## Threading

The window and the sign-in dialog live on the UI thread. The whole
"sign in → update → start the tool" flow runs on a worker thread and talks to the
UI through messages, so the window never freezes and the progress bar moves.
Network calls that belong to the sign-in dialog run on a short-lived worker
thread while the dialog keeps pumping messages.

## Build details

- Target: `x86-windows-gnu` (32-bit, like `PandoraTool.exe`), subsystem
  `windows`, static link, `-Os`, imports only WinHTTP / comctl32 / shell32 /
  version / advapi32 / user32 / gdi32 plus the OS universal CRT.
- The manifest declares `asInvoker` (the launcher offers to restart itself
  elevated when an update hits "access denied") and Common Controls v6.
- The self-test data (a real update package with deflate/store members,
  non-ASCII names, an empty file and a hostile `../` package) is generated by
  `tools/make-fixtures.py` into `tests/testzip.h`, `tests/expected.h`,
  `tests/deflate.h` and `tests/hostilezip.h`, so `PandoraLauncher.exe --self-test`
  can unpack and verify a real package on the user's machine.
